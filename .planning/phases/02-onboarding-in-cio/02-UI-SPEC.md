## Typography

Phase 1 sizes 12/14/16/20 + weights 400/600 stay. **Phase 2 adds exactly ONE display size** (explicitly deferred from Phase 1, A6). No new weight: the display uses 600, so the app still loads only 2 weights.

| Role | Size | Weight | Line Height | Used for in Phase 2 |
|------|------|--------|-------------|---------------------|
| Caption | 12px | 400 / 600 (badges) | 16px (1.33) | Badge text (severity, status, metric marks), MetricTile context line |
| Label | 14px | 600 field labels + hero overline; 400 secondary text | 20px (1.43) | Property/city line, "Atualizado há…", counts lines, alert subtitles, form helper/error |
| Body | 16px | 400; 600 for card primary lines + buttons | 24px (1.5) | Hero reason (600) + action (400), climate condition (600), alert titles in rows (600), alert description/recommendation |
| Heading | 20px | 600 | 28px (1.4) | Greeting, section titles, onboarding title, alert-detail title, **MetricTile values** |
| **Display (new)** | **28px** | **600** | **36px (1.29)** | **Hero status word only: "Normal" / "Atenção" / "Crítico"** |

- **Justification for Display 28:** the condition word is the product's core value (PROJECT core value; ROADMAP SC-2 "large indicator") and must be read at arm's length in sunlight. 28 is +40% over the 20 heading — clearly dominant — while "Atenção"/"Crítico" at 28/600 (~110px wide) still fits next to a 56 icon circle at 360px width and at 200% font scale (wraps, never clips). It is used for ONE element on ONE screen; using it anywhere else is a contract violation.
- Implementation: add `display: { fontSize: 28, lineHeight: 36 }` to `typography` in `tokens.ts`; `Text` gets `variant="display"` automatically through `TypographyVariant`.
- Numerals: `numeric` (`tabular-nums`) on MetricTile values, climate stats, counts, times.
- `allowFontScaling` on everywhere. Hero word: no `maxFontSizeMultiplier` cap; it wraps.

## Screen Contracts

### S1. Onboarding — `src/app/(app)/onboarding.tsx` (ONB-01, ONB-02)

**Gate:** shown when `producers.onboarding_completed_at` is null (route guard, `Stack.Protected` pattern from root layout). No tab bar, no back button, not skippable. While the guard is resolving: full-screen `LoadingState` "Preparando sua propriedade…".

**Focal point:** the first empty field; the primary button is the only filled (accent) element.

Layout: `ScreenHeader brand` (Logo 32 + wordmark) → `ScreenContainer` (ScrollView, `keyboardShouldPersistTaps="handled"`, wrapped in `KeyboardAvoidingView` `behavior="padding"` on iOS):
1. Title block: "Configure sua propriedade" Heading 20/600 (`accessibilityRole="header"`) → 4 → subtitle Label 14/400 muted.
2. 24 → `Card` (default, padding 16), header row: `House` 20 `text` + 8 + "Sua propriedade" Body 16/600 → 16 → fields (gap 16):
   - **Nome da propriedade** — `Input`, value prefilled with the current property name (cloned "Minha Propriedade"), `autoCapitalize="words"`, return "next"
   - **Cidade** — `Input`, empty, placeholder "Ex.: Campinas", `autoCapitalize="words"`, `autoComplete="off"`, return "next" → focuses Nome da área (UF is a tap)
   - **Estado** — `Select`, placeholder "Selecione o estado", 27 options, label "{Nome} ({UF})" sorted by name (e.g. "São Paulo (SP)"); stored value = 2-letter UF
3. 24 → `Card` (default), header row: `Sprout` 20 + 8 + "Primeira área de plantio" Body 16/600 → 4 → helper Label 14/400 muted → 16 → fields:
   - **Nome da área** — `Input`, placeholder "Ex.: Talhão 1", return "next"
   - **Cultura** — `Input`, placeholder "Ex.: Milho", `autoCapitalize="sentences"`, return "done" submits
4. Form-level `Notice error` (only after a failed save), 16 above the button.
5. 32 → `Button primary md fullWidth` "Concluir configuração" (loading "Salvando…"; all fields disabled while saving).
6. 16 → `Button ghost sm` centered "Sair da conta" → opens the inherited logout `Modal` (Phase 1 copy). Prevents trapping the user if saving keeps failing.

**Validation:** on submit only (then live per field once shown). Values trimmed. Limits: property/area name 1–120, city 2–80, crop 1–60. Errors inline under the field (Phase 1 `Input` error contract); focus moves to the first invalid field.

**States:**

| State | Behavior |
|-------|----------|
| loading (prefill fetch) | `LoadingState` "Carregando sua propriedade…" |
| load error | `ErrorState` (generic network copy, retry refetches) + ghost "Sair da conta" below |
| idle / editing | form as above |
| saving | button loading "Salvando…", inputs disabled, screen not dismissable |
| save error | `Notice error` save copy; values kept; button re-enabled. Retry must not create a duplicate area (planner: make insert idempotent or skip if already created) |
| success | `router.replace` to Início (no success screen, no toast). Query cache for property/home invalidated so Início shows the new name immediately |

### S2. Início — `src/app/(app)/(tabs)/index.tsx` (HOME-01..08)

**Focal point:** the hero "Condição da propriedade" card. Visual hierarchy: hero (Display 28, tinted, 2px border) > section titles (20) > metric values (20) > everything else. Greeting is secondary.

`ScreenHeader brand` → `ScreenContainer` with `refreshing` / `onRefresh` (pull-to-refresh refetches property, condition inputs, climate, alerts in parallel). Section gap 24. Top to bottom:

**1. Greeting (HOME-01)**
- "Olá, {primeiro nome}" Heading 20/600 (`accessibilityRole="header"`)
- 4 → row: `MapPin` 16 `textMuted` + 4 + Label 14/400 muted, `numberOfLines={2}`: "{Propriedade} · {Cidade}/{UF}" (no city → "{Propriedade}").

**2. Hero "Condição da propriedade" (HOME-02, HOME-06)** — `ConditionHero`
- Container: radius 16, padding 24, 2px border + soft bg per Color table. Not pressable as a whole.
- Content block (one `accessible` View, `accessibilityLabel` = "Condição da propriedade: {Status}. {reason} {action} {+N line}", `accessibilityLiveRegion="polite"` so a status change after refresh is announced):
  - Overline "Condição da propriedade" Label 14/600 `text`
  - 12 → row: 56 circle (`card` bg) with status icon 32 → 12 → status word Display 28/600 (status color)
  - 12 → reason line Body 16/600 `text`
  - 4 → action line Body 16/400 `text`
  - (if more reasons) 8 → "+N outros pontos de atenção" Label 14/600 `text`
- 16 → action button (`Button secondary sm`), only when not Normal:
  - top reason is an alert → "Ver alerta" → alert detail of that alert
  - top reason is out-of-range or offline → "Ver monitoramento" → Monitoramento tab
- 16 → 1px divider (`border`) → 12 → footer row, `justifyContent: space-between`: left `Clock` 16 + 4 + "Atualizado há X min" Label 14/400 `textMuted` (`numeric`); right `Button ghost sm` with `RefreshCw` 20 "Atualizar" (loading "Atualizando…") — the refresh path on web, also present on native.

Reason/action rules (D-06 priority: critical alert → warning/info alert → out-of-range → offline; within a tier newest first):

| Top reason | Reason line | Action line |
|-----------|-------------|-------------|
| Alert (any severity) | `alerts.title` + " — {área}" when the alert's sensor has an area, else title alone | `alerts.recommendation` (verbatim from DB) |
| Out of range | "{Medida} {acima do limite \| abaixo do mínimo} — {área ou nome do sensor}" | fixed copy per type/direction (Copy table) |
| Sensor offline | "Sensor sem comunicação — {nome do sensor}" | "Verifique a bateria, o sinal e a conexão do sensor." |
| Normal (D-07) | "Tudo certo na sua propriedade." | "Sensores funcionando e sem alertas pendentes." |
| Normal, zero sensors | "Nenhum alerta pendente." | "Cadastre sensores em Monitoramento para acompanhar as leituras." |

Dedup: an offline sensor that also has an open `sensor_offline` alert counts as ONE reason (the alert). Same for an out-of-range reading with an open alert on the same sensor. "+N" counts the remaining distinct reasons.

**3. Clima agora (HOME-03)** — `SectionHeader` "Clima agora" (no action) → `ClimateCard` (`Card` default):
- Row: 48 circle (`background` bg) with condition icon 24 `text` → 12 → column: `climate_snapshots.condition` Body 16/600; description Label 14/400 muted (wraps).
- 16 → 1px divider → 12 → 3 equal stats (`flex: 1`, gap 8), each: Label 14/400 muted label above, Body 16/600 `numeric` value: "Temperatura" "27 °C" · "Umidade" "74%" · "Chuva" "80%". Null value → "—".
- Icon map by `condition` (case-insensitive contains): "tempest" → `CloudLightning`; "chuv"/"garoa" → `CloudRain`; "parcial" → `CloudSun`; "nublado" → `Cloud`; "sol"/"limpo"/"ensolarado" → `Sun`; else `Cloud`.
- No snapshot → card shows `Cloud` icon + "Clima indisponível" + "Ainda não há dados de clima para sua propriedade." (no stats row).
- Not pressable.

**4. Indicadores (HOME-04, HOME-05, HOME-08)** — `SectionHeader` "Indicadores" with action "Ver monitoramento" → Monitoramento tab.
- Row of 3 `MetricTile`s (`flex: 1`, gap 8). When `fontScale >= 1.3` OR window width < 360 → stack vertically (gap 8). Each tile `onPress` → Monitoramento tab.
  - Temperatura · `Thermometer` · unit "°C"
  - Umidade do ar · `Droplets` · unit "%"
  - Umidade do solo · `Sprout` · unit "%"
- **Which value per type (decision):** only online sensors (D-05) count. If any online sensor of the type is out of range → show that sensor's latest reading (the one furthest outside the range, by % of the violated limit), mark "Atenção", context = its area name (fallback sensor name). Else → arithmetic mean of online sensors' latest readings, mark "Normal", context = "Média de {n} sensores" (n=1 → area name). No online sensor → value "—", no unit, mark "Sem dados", context "Nenhum sensor online".
- Number format: pt-BR, 1 decimal max, comma ("27,4"); humidity values rounded to integer.
- 12 → counts line: `Radio` 16 `textMuted` + 4 + Label 14/400 muted `numeric`: "{a} sensores ativos · {o} sem comunicação" (omit the " · …" part when o = 0). Zero sensors: tiles replaced by inline `EmptyState` (inside a `Card`): icon `Radio`, "Nenhum sensor cadastrado", body, action "Ver monitoramento".

**5. Alertas recentes (HOME-05, HOME-07)** — `SectionHeader` "Alertas recentes" with action "Ver todos" → Alertas tab.
- 0 → pending count Label 14/400 muted `numeric` ("{n} alertas pendentes"), then 12 → `Card` with padding 0 containing up to 3 `AlertRow`s (unresolved = `novo` + `visualizado`; order severity critical → warning → info, then `triggered_at` desc). Last row `isLast` (no divider).
- `AlertRow`: `Pressable`, `minHeight 72`, padding 16 horizontal / 12 vertical, gap 12, pressed bg `background`:
  - lead 40 circle (severity bg) with severity icon 20
  - body (`flex: 1`): title Body 16/600 `numberOfLines={2}` → 4 → subtitle Label 14/400 muted `numberOfLines={1}` "{área ou 'Propriedade'} · {tempo relativo}" → 8 → badge row (gap 8): severity Badge + status Badge
  - trailing `ChevronRight` 20 `textMuted`
  - a11y: `accessibilityRole="button"`, label "{Severidade}: {título}. {subtitle}. {status}. Abrir detalhes"
  - `onPress` → alert detail
- Empty (no unresolved alerts): `Card` containing compact row: 40 circle `successSoft` + `CircleCheck` 20 `success` → 12 → "Nenhum alerta pendente" Body 16/600 + body Label 14/400 muted. Count line hidden.

**Screen states:**

| State | Behavior |
|-------|----------|
| first load | `LoadingState` "Preparando sua propriedade…" (whole screen, inherited) |
| first-load error | `ErrorState` generic network copy, retry refetches all |
| no property (inherited empty) | Phase 1 EmptyState (`Sprout`, copy unchanged) |

Relative time (`formatUpdatedAgo`, shared helper, unit-tested): < 1 min → "Atualizado agora"; 1–59 min → "Atualizado há {n} min"; 1–23 h → "Atualizado há {n} h"; >= 24 h → "Atualizado em {dd/MM} às {HH:mm}"; no reading → "Sem leituras recentes". ## Interaction & Accessibility (additions)

- Condition is always icon + word + color (hero, badges). The hero word is real text, never an image.
- Hero content block announces status changes (`accessibilityLiveRegion="polite"`; iOS `announceForAccessibility` when status differs from the previous render).
- Every pressable (tiles, alert rows, section actions, back) >= 48 target with pressed feedback; MetricTile/AlertRow pressed bg `background`.
- Pull-to-refresh is never the only path: the hero "Atualizar" button does the same refetch (web + a11y).
- Tab order on web follows the visual order; focus ring inherited.
- 200% text: MetricTiles stack; hero word wraps; alert titles wrap to 2 lines; no fixed heights.
- Onboarding return keys chain fields; Select opens with Enter/Space on web.
