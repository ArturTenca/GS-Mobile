## Summary

The repo already has a small security base: `src/lib/security/{limits,sanitize,validate}.ts` (+ 1 test file), PKCE recovery with code validation, a client-side login cooldown, UUID validation of URL params, a Leaflet document with no user text, a CSP, SRI and a sandboxed iframe, and a DB with RLS, column-level grants and CHECK constraints. Baseline is green: `npx jest` = 43 suites / 385 tests pass; `npx jest src/features/auth --bail` = 3 suites / 23 tests pass; `tsc --noEmit` clean. [VERIFIED: ran in this session]

The SQL-injection surface is effectively zero: no string-built PostgREST filters (`.or/.ilike/.filter` do not appear in `src/services`), the only `execute` in migrations is a static `net.http_post` with `USING` parameters, and every `format()` uses `%s` for display text (not for SQL). The real gaps are: (1) free-text fields are not normalized/neutralized and have client/DB limit mismatches, (2) text from external APIs (BrasilAPI/ViaCEP) flows into form → DB unsanitized, (3) no PII-in-wrong-field control (a farmer can put a CPF/phone into a sensor name, which then goes into `alerts.description` and a **push notification body** to Expo servers), (4) `ServiceError.cause` keeps raw PostgREST errors (Postgres check-violation `details` can echo the failing row), and (5) several concrete auth bugs (see section 2). Login has 9 confirmed issues; the worst is `mapAuthError` mapping every unknown code (e.g. `email_not_confirmed`, `same_password`) to "Sem conexão".

Recommended design: a dependency-free, erasable-syntax-only TypeScript PII engine in `src/security/pii/` (runs in jest, in the app, and in Node CLI via native type stripping); runtime taint = **sink guards** that call the engine (strings are primitives and cannot carry tags) plus a `Tainted<T>` brand only for the 3 highest-risk flows; static taint = a ~300-line **TypeScript compiler API** tracer (verified: `typescript` 6.0.3 builds the 211-file program in ~2.2 s); AI remediation = Edge Function `explain-risk` that receives only allowlisted `{rule_id, severity, sink, action, count}` (no user text can reach the prompt), caches by fingerprint, falls back to deterministic pt-BR templates; dashboard = new route `src/app/(app)/seguranca.tsx` plus a new `SecuritySection` component, touching `perfil.tsx` in only 2 additive lines.

**Primary recommendation:** Build engine → sink guards + static tracer → DB migration 010 + `explain-risk` → dashboard → sanitization/auth fixes in parallel; never hash raw PII values for persistence (CPF space is brute-forceable) — fingerprint `(rule_id, sink, origin_field)` instead.

### Pattern 1: Declarative PII rule
```typescript
// Source: design for this phase (D-01/D-02)
export type Rule = {
  id: string;                     // 'cpf', 'cnpj', 'email', 'br_phone', 'cep', 'rg', 'card', 'jwt', ...
  category: 'identity'|'contact'|'financial'|'credential'|'health'|'location'|'address';
  severity: 'low'|'medium'|'high'|'critical';
  pattern: RegExp;                // global, bounded, linear-time (no nested quantifiers)
  validate?: (match: string, ctx: { before: string; after: string }) => boolean;
  contextWords?: { words: RegExp; window: number; required: boolean };
  redact: 'mask-keep-last2' | 'mask-email' | 'tag' | 'drop';
};
```

### Pattern 2: Sink guard (runtime taint enforcement)
```typescript
// Source: design for this phase (D-04/D-05)
export function guardSink<T extends string | Record<string, unknown>>(
  sink: SinkId, payload: T, ctx: { origin: string },
): { payload: T; blocked: boolean; findings: Finding[] } {
  const policy = SINK_POLICY[sink];                  // { action: 'block'|'redact', categories: Set<Category> }
  const text = typeof payload === 'string' ? payload : JSON.stringify(payload);
  const findings = scan(text).filter((f) => policy.categories.has(f.category));
  if (findings.length === 0) return { payload, blocked: false, findings };
  recordEvent({ sink, origin: ctx.origin, findings, action: policy.action }); // redacted preview only
  if (policy.action === 'block') throw new TaintBlockedError(sink);           // caller maps to pt-BR message
  return { payload: redactDeep(payload, findings), blocked: false, findings };
}
```

### Pattern 3: Edge Function mirrors push-alert
Pure `logic.ts` (validation of allowlisted input, prompt/schema builder, response validation, templates, fingerprint) tested by jest; `index.ts` (Deno, SDK, supabase-js, CORS) excluded from tsc. Add `supabase/functions/*/index.ts` is already in `tsconfig.exclude`; `logic.test.ts` is picked up by jest. `config.toml` needs `[functions.explain-risk] verify_jwt = true` (push-alert uses `false` because it authenticates by shared secret; explain-risk must NOT).

### Anti-Patterns to Avoid
- **Hashing raw CPF/phone/e-mail for storage** (D-06 says "hashes"): CPF has ~10^9 valid values; an unsalted hash is reversible by brute force. Persist `fingerprint = hash(rule_id|sink|origin_field)` and a preview that is already masked.
- **Letting the model see user text.** Build the prompt only from allowlisted `rule_id`/`severity`/`sink`/`action`/`count`; descriptions come from a server-side catalog. This also removes prompt-injection risk entirely.
- **Regex with nested quantifiers** in rules (ReDoS) — bound input length (scan caps at 10 000 chars/field) and use linear patterns.
- **Flagging every 11-digit number as CPF** — always validate check digits and reject repeated-digit sequences (`111.111.111-11`).
- **Blocking legit address text**: `street`/`neighborhood`/`city` are address by nature; the guard only blocks *non-address* PII (CPF, phone, e-mail, card, health, secrets) in those fields.

### 4.2 Runtime enforcement (recommended)
JS strings are primitives and cannot carry taint tags. Therefore:
1. **Content-based sink guards** (above) are the enforcement mechanism — "dynamic taint by detection". State this limitation honestly in the audit.
2. A thin `Tainted<T>` wrapper (`{ value, source, labels }` with `unwrap(sink)` that runs `guardSink`) is used only on three explicit flows to demonstrate tracked propagation: (a) `street`/`city` form value → geocoding query, (b) `sensors.name` → push body, (c) error object → log. Do **not** thread it through the whole UI (1.5-day budget).
3. Events: guard calls `recordEvent` (in-memory ring buffer, max 100) → batched flush through `src/services/security.ts` → RPC `record_security_events`. Buffer flush must be non-blocking and never throw into the user flow.
4. Mapping blocked sink to UX: `TaintBlockedError` → pt-BR message via services (e.g. "Esse texto parece conter um dado pessoal (CPF/telefone). Remova antes de continuar.").

### 4.3 Static tracer: recommendation = TypeScript compiler API

Key decisions:
- **Auth:** keep gateway `verify_jwt = true` (add `[functions.explain-risk] verify_jwt = true` in `supabase/config.toml`; note the existing push-alert entry is `false`) **and** `auth.getUser()` in code; no body field selects another user's data (the function never reads user rows — input is the metadata the client already owns). CORS handling is required because RN Web calls `supabase.functions.invoke` from the browser (headers `authorization, x-client-info, apikey, content-type`) — push-alert never needed this.
- **Prompt content:** `{ rule_id, severity, sink, action, count }` plus catalog text from `logic.ts` (`RULE_CATALOG[rule_id]`). No previews, no field values, no user ids. Outbound guard: `scan(JSON.stringify(prompt))` must return `[]` else skip the call (taint rule on the LLM sink). Prompt-injection surface is nil since no free text is included.
- **Schema (D-08):** `{ titulo: string, risco_real: string, o_que_fazer: string, nivel: 'baixo'|'moderado'|'alto'|'critico' }` wrapped as `{ alertas: [ {rule_id: enum(allowlist), ...} ] }`, `additionalProperties:false`. Use enums rather than `maxLength` (not enforceable); enforce lengths (`titulo ≤ 80`, `risco_real ≤ 280`, `o_que_fazer ≤ 280`) in `validateModelJson`, reject any output matching the PII engine or containing `http`/markup.
- **Cache:** table `security_ai_cache(fingerprint primary key, rule_id, payload jsonb, model text, source text, prompt_version int, created_at)`; fingerprint = sha256(`PROMPT_VERSION|rule_id|severity|sink|action`) so it is user-agnostic; RLS on, `select` to `authenticated`, no write grants (service role bypasses). Template-sourced rows are **not** cached (so a later deploy of the key upgrades them).
- **Output contract to client:** `{ items: [{rule_id, titulo, risco_real, o_que_fazer, nivel, source:'ai'|'template'}], model?: string, servedByFallback?: boolean }`. The UI shows "Explicado por IA" vs "Texto padrão" honestly.
- **Failure ladder:** no key → templates; SDK throws (401/429/529/timeout) → templates; `stop_reason==='refusal'` (after server-side fallback declined or no fallback category) → templates; `max_tokens`/invalid JSON/validation failure → templates; function unreachable (404/network, e.g. not deployed yet) → client-side templates from `src/security/remediation/templates.ts`. A jest parity test asserts the function's template table equals the client's (push-alert already duplicates constants by comment; parity test is the improvement).
- **Cost/abuse controls:** ≤ 12 items/request, ≤ 6 uncached per request, 1 500 max_tokens, `effort:'low'`, per-user daily cap enforced by counting rows in a tiny `security_ai_calls` table or simply by cache (misses are bounded by ~|rules|×|sinks|). Treat cap as optional.
- **Model note:** the CONTEXT model is `claude-opus-5-5` (supported for structured outputs, effort and fallbacks per the docs above). Cheaper `claude-haiku-5-5` has **no** server-side fallback; do not switch without revisiting D-08.

### 6.2 Score formula (proposal, documented + unit-tested)
Higher = more risk (0 = nothing exposed). For each event not `resolved`:
`points = W_sev[severity] × min(occurrences, CAP) × M_action`, with `W_sev = {low:1, medium:4, high:10, critical:25}`, `CAP = 5`, `M_action = {detected:1.0, redacted:0.5, blocked:0.25}` (a blocked leak is mitigated but evidences a risky behaviour).
`raw = Σ points`; `score = round(100 × (1 − e^(−raw/60)))` (smooth saturation: no single bad finding pins the score at 100, many do).
Levels: `0–24 baixo`, `25–49 moderado`, `50–74 alto`, `75–100 crítico`. Boundary and monotonicity tests: score never decreases when adding an event; `resolved` events contribute 0; empty → 0/baixo; one critical `detected` (25) → 34/moderado; 3 critical `detected` → 71/alto; 5 critical → 87/crítico. UI maps levels to icon+text+color (never color alone) using the existing semantic colors/Badge components.

## Common Pitfalls

### Pitfall 1: CPF false positives wreck the "robustez" score
**What goes wrong:** every 11-digit id/phone is flagged. **Why:** regex only. **Avoid:** mod-11 + all-equal rejection + overlap priority; property tests (3.3). **Warning sign:** scanning the seed SQL (`003`, `007`) reports CPFs.

### Pitfall 2: Persisting hashes of PII
**What goes wrong:** brute-forceable. **Avoid:** fingerprint metadata, not values (Anti-patterns).

### Pitfall 3: Taint "guard" that logs the raw value
**What goes wrong:** the audit event itself leaks. **Avoid:** engine returns spans; only `redact()` output is stored/printed; jest test asserts `JSON.stringify(event)` contains no raw match.

### Pitfall 4: CORS on the Edge Function (web)
**What goes wrong:** works on phone, fails on `expo start --web` (preflight OPTIONS 4xx). **Avoid:** handle OPTIONS and return CORS headers on every response including errors.

### Pitfall 5: `fallbacks` + wrong beta string / wrong client
`fallbacks` is only on `client.beta.messages.create` with the exact `server-side-fallback-2026-07-01` header; any other `server-side-fallback-*` value → 400. Treat any thrown error as "use templates".

### Pitfall 6: Opus 5.5 defaults to `medium` effort and always thinks
Omitting `effort` costs more/slower; sending `thinking:{type:"disabled"}` is a 400. Set `effort:'low'`, give `max_tokens` headroom (thinking counts) — 1 500 is enough for ≤ 6 short alerts at low effort; keep ≤ 6 items per call.

### Pitfall 7: Edge Function imports `src/`
`supabase functions deploy` bundles only the function directory (assumed); importing `../../../src/security/...` may fail. Keep the function self-contained (`logic.ts` with a small guard + parity tests), as push-alert already does.

### Pitfall 8: Perfil merge conflicts
Do not reorder or reformat `perfil.tsx`; two additive lines only; last task; do not touch `_layout.tsx`, `package.json`, `app.json`.

### Pitfall 9: Rejecting legit pt-BR names/addresses
Allowlist must use `\p{L}\p{M}` (accents, ç, ã) and common punctuation (`'`, `-`, `.`, `º`, `ª`, `/`, `,`, `()` and digits for addresses); test with "João D'Ávila", "Sítio São José – Km 12", "R. 7 de Setembro, nº 45".

### Pitfall 10: Cooldown/lockout used as security
Client cooldown is UX only (resets on reload); rely on Supabase server limits and document it (already in `useLoginRateLimit` comment).

### CPF validator (mod-11)
```typescript
// Source: standard Receita Federal algorithm
export function isValidCpf(raw: string): boolean {
  const d = raw.replace(/\D/g, '');
  if (d.length !== 11 || /^(\d)\1{10}$/.test(d)) return false;
  const dv = (len: number) => {
    let sum = 0;
    for (let i = 0; i < len; i++) sum += Number(d[i]) * (len + 1 - i);
    const r = (sum * 10) % 11;
    return r === 10 ? 0 : r;
  };
  return dv(9) === Number(d[9]) && dv(10) === Number(d[10]);
}
```

### Luhn
```typescript
export function luhn(raw: string): boolean {
  const d = raw.replace(/\D/g, '');
  if (d.length < 13 || d.length > 19) return false;
  let sum = 0, alt = false;
  for (let i = d.length - 1; i >= 0; i--) {
    let n = Number(d[i]);
    if (alt) { n *= 2; if (n > 9) n -= 9; }
    sum += n; alt = !alt;
  }
  return sum % 10 === 0;
}
```

### Score
```typescript
const W = { low: 1, medium: 4, high: 10, critical: 25 } as const;
const M = { detected: 1, redacted: 0.5, blocked: 0.25, resolved: 0 } as const;
export function computeRiscoCidadao(events: { severity: keyof typeof W; action: keyof typeof M; occurrences: number }[]) {
  const raw = events.reduce((s, e) => s + W[e.severity] * Math.min(e.occurrences, 5) * M[e.action], 0);
  const score = Math.round(100 * (1 - Math.exp(-raw / 60)));
  const level = score >= 75 ? 'critico' : score >= 50 ? 'alto' : score >= 25 ? 'moderado' : 'baixo';
  return { score, level, raw };
}
```

### Known Threat Patterns

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| SQL injection via free text | Tampering | Parameterized supabase-js/RPC; DB CHECKs; lint rule against template-literal filters |
| Stored XSS via names (web) | Tampering | RN `<Text>` only; no `dangerouslySetInnerHTML`; allowlist chars; map has no user text |
| PII leak to third parties (Nominatim, Expo Push, LLM) | Information disclosure | Sink guards + policies + events |
| Prompt injection into LLM | Tampering | No free text in prompt; enum-validated output; output PII scan |
| Secret in repo/ZIP | Information disclosure | Scanner over file list; `.env` excluded; function-side secret only |
| Account enumeration | Information disclosure | Uniform login/reset messages; decision on signup |
| Double-submit / reset spam | DoS | in-flight ref lock; resend guard; server limits |
| Open redirect / deep-link abuse | Spoofing | No redirect params; reset `code` regex + PKCE; `assertAllowedUrl` |
| Event-table spam | DoS | RPC caps; unique fingerprint upsert |
| Bidi/zero-width spoofing in names | Spoofing | Strip U+202A–202E, U+2066–2069, U+200B–200F |
