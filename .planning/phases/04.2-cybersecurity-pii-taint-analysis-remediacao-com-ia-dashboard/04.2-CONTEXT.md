<domain>
## Phase Boundary

Deliver the Cybersecurity course module inside the AgroAlerta repo by 19/11/2026: a PII parsing engine with rules (CPF, health, passwords and other sensitive data), a taint-analysis layer that tracks collected data from input sources to outputs and blocks leaks into unsafe sinks, an LLM (Claude) remediation step that turns technical findings into plain pt-BR citizen risk alerts, and an in-app "Risco Cidadão" executive dashboard. Also harden every input field against SQL injection, XSS and related attacks, and find and fix login/auth bugs. Package the module and audit evidence for a ZIP delivery.

</domain>

<decisions>
## Implementation Decisions

### PII parsing engine (3,0 pts — locked)
- D-01: A standalone, testable TypeScript module (e.g. `src/security/pii/`) with a declarative rule set: CPF (with check-digit validation, masked/unmasked), CNPJ, e-mail, phone (BR), CEP, RG, credit card (Luhn), passwords/secrets/tokens (JWT, `sb_`/`sk-` keys, `password=` patterns), health data (CID-10 codes and pt-BR health keywords), precise geolocation (lat/lng). Each rule has id, category, severity, regex/validator, and a redaction strategy.
- D-02: The engine returns structured findings (rule, category, severity, span, redacted preview) and a `redact()` helper. False-positive control (validators, context words) and a jest suite with positive/negative fixtures prove robustness.
- D-03: A CLI/scanner (Node script) runs the same rules over the repository and over exported/seeded data, producing an audit report (JSON + markdown) — evidence for "Auditoria do Protótipo".

### Taint analysis (3,0 pts — locked)
- D-04: Mark data from untrusted sources (all user inputs: text fields, URL params/deep links, external API responses) as tainted; define sinks (logs/console, error messages shown to user, analytics, third-party requests such as Nominatim/Open-Meteo, LLM prompts, push payloads, clipboard/share). Tainted PII reaching an unsafe sink must be blocked or redacted, and the event recorded.
- D-05: Provide runtime enforcement (wrappers/guards at sinks) plus a static check (script that traces source→sink flows in `src/` and fails on unsafe flows), with tests and a written audit showing flows caught and blocked ("em ação").
- D-06: Findings/events are persisted in Supabase (new table, owner-scoped RLS, no raw PII stored — only redacted previews and hashes) to feed the dashboard.

### Remediação com IA (2,0 pts — locked)
- D-07: Supabase Edge Function calls Claude via the official Anthropic TypeScript SDK (`npm:@anthropic-ai/sdk` in Deno). Model `claude-opus-5-5` (skill default; user did not name a model). API key only as Supabase secret `ANTHROPIC_API_KEY`; never in the app or git.
- D-08: Use structured outputs (`output_config.format` JSON schema) returning {titulo, risco_real, o_que_fazer, nivel}. Send ONLY redacted findings (taint rule applies to the LLM sink itself). Handle `stop_reason: "refusal"` (security content can trigger the `cyber` classifier) and enable server-side fallbacks (`betas: ["server-side-fallback-2026-07-01"]`, `fallbacks: "default"`). On any failure or missing key, fall back to deterministic pt-BR templates. Cache translations per finding fingerprint in the DB to avoid repeated calls. Opus 5.5: do not send `thinking: {type:"disabled"}` or `budget_tokens`; set `output_config.effort` explicitly (low is enough).

### Dashboard Executivo — Risco Cidadão (2,0 pts — locked)
- D-09: New in-app screen reachable from Perfil (e.g. "Segurança e privacidade"), native + web, using existing components/tokens. Shows the Risco Cidadão indicator (0–100 score + level baixo/moderado/alto/crítico with icon+text+color), counts by category/severity, recent findings/blocked leaks, the AI-translated alerts, and a "Rodar auditoria" action. Score formula documented and unit-tested.

### Input sanitization (user request — locked)
- D-10: Every input field in the app (auth, farm form incl. CEP/endereço/bairro, sensor name, thresholds, profile name, filters/search) passes through centralized validation + sanitization: trim, length limits, allowlists for formats, strip control chars, reject/neutralize HTML/script payloads. Never build SQL strings: keep Supabase parameterized queries/RPCs; audit RPCs/SQL functions for dynamic SQL (`execute format` with `%I`/`%L` only). DB-level CHECK constraints mirror client limits where missing. Web build: no `dangerouslySetInnerHTML`; Leaflet/WebView HTML must escape user text; add a CSP where applicable.

### Login / auth bugs (user request — locked)
- D-11: Audit the auth flows (Entrar, Criar conta, recuperação de senha, sessão persistida, logout, guards) and fix bugs found (error mapping, double-submit, session restore races, redirect loops, weak password rules, e-mail enumeration in messages). Each fix gets a regression test where feasible.

### Delivery
- D-12: ZIP-ready package: module code + rules, audit report (taint evidence), README section "Cybersecurity", screenshots/video placeholders for the dashboard (human captures), and a script to build the ZIP excluding node_modules/.env.

### Claude's Discretion
- Exact file layout, rule regexes, score formula weights, Edge Function name, table names.
- How static taint tracing is implemented (AST via TypeScript compiler API vs simpler pattern tracing) given the deadline.

</decisions>
