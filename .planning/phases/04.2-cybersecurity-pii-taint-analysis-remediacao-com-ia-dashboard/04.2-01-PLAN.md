<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| text input -> engine | arbitrary user/repo text enters scan(); ReDoS and oversized input risk |
| engine -> logs/reports/DB | anything the engine emits could re-leak PII |
| repo files -> scanner report | reports are committed and zipped |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04.2-01 | Denial of Service | scan() regexes | mitigate | linear bounded patterns only, maxLength 10000 cap, property test with long adversarial strings finishing under a time budget |
| T-04.2-02 | Information Disclosure | Finding / report output | mitigate | Finding has no raw field; previews pre-redacted; tests assert JSON.stringify(findings) and reports lack the raw value |
| T-04.2-03 | Information Disclosure | pii-scan report committed to git | mitigate | report prints file:line:rule:preview only; allowlist requires reason; fixtures assemble secrets at runtime |
| T-04.2-04 | Tampering | false negatives via obfuscation (spaces, zero-width) | mitigate | NFKC + zero-width stripping + spaced patterns; evasion tests |
| T-04.2-05 | Information Disclosure | repo secrets (.env) | mitigate | scanner skips nothing silently for .env: it only walks git-tracked/unignored files, never reads .env values |
| T-04.2-SC | Tampering | npm/pip/cargo installs | accept | this plan adds no packages (zero new dependencies) |
</threat_model>
