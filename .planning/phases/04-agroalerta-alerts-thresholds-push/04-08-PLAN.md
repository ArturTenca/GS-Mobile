## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DB trigger / webhook -> Edge Function | Public HTTPS endpoint with verify_jwt disabled |
| Edge Function -> Supabase | Service-role client (full DB access) |
| Edge Function -> Expo Push API | Outbound with optional access token |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-23 | Spoofing | forged call to push-alert | mitigate | Shared-secret header `x-push-secret`, constant-time compare, 401 before any DB access |
| T-04-24 | Elevation | service-role key | mitigate | Used only inside the function via runtime env; never in app code or repo (grep criterion) |
| T-04-25 | Information disclosure | notification content on lock screen | mitigate | Title/body contain only severity, alert title, farm and area/sensor names; no coordinates or readings |
| T-04-26 | Tampering | push spam / duplicate pushes | mitigate | `notified_at` checked before and set after (guarded `.is('notified_at', null)`); payload limited to alert id |
| T-04-27 | Spoofing | token reuse across users | mitigate | Tokens fetched strictly by the alert owner's user_id; DeviceNotRegistered tokens deleted |
| T-04-28 | Denial | malformed body | mitigate | Defensive JSON parse, UUID validation, 400 on invalid |
| T-04-SC | Tampering | npm/jsr dependencies | mitigate | Only `jsr:@supabase/supabase-js@2` (first-party Supabase); no new npm packages |
</threat_model>
