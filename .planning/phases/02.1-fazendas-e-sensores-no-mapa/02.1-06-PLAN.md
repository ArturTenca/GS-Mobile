## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| map document -> React host | postMessage events from WebView/iframe are untrusted |
| CDN -> map document | Leaflet script/CSS from unpkg/jsdelivr |
| tile servers -> map | Esri and OSM imagery |
| host app -> iframe | scene data pushed into the page |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.1-20 | Spoofing/Tampering | MapCanvas message handlers | mitigate | parseMapEvent validates shape/range/size; web handler requires e.source === iframe.contentWindow |
| T-02.1-21 | Tampering | Leaflet CDN compromise | mitigate | Pinned 1.9.4 + SRI hashes (test asserts), CSP limits script/img hosts, page holds no credentials (iframe sandbox allow-scripts without allow-same-origin, WebView has no app tokens) |
| T-02.1-22 | Tampering | XSS via farm/sensor names in map HTML | mitigate | Names never enter the HTML/scene; only coordinates, radii and kinds; test forbids innerHTML/eval/document.write |
| T-02.1-23 | Tampering | WebView navigation hijack | mitigate | onShouldStartLoadWithRequest allows only about:blank/data:/baseUrl; setSupportMultipleWindows false |
| T-02.1-24 | Denial of service | tile providers blocking the app | accept | Street layer lazy-loaded, attribution visible, no prefetch; URLs configurable in mapTiles.ts (documented swap to keyed provider) |
| T-02.1-SC | Tampering | npx expo install react-native-webview | mitigate | Expo-bundled version (14.0.1) from bundledNativeModules; npm view check; no postinstall script |
</threat_model>
