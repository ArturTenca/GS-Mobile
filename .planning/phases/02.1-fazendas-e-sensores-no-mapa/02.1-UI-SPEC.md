### New tokens — map overlays (add to BOTH `lightColors` and `darkColors` with the SAME values)

Drawn on satellite and street imagery, so they are theme-independent and chosen for visibility on green vegetation AND on the light OSM map (a dark halo is drawn under every line/marker).

| Token | Value (light = dark) | Usage |
|-------|---------------------|-------|
| `mapBoundary` | `#4ADE80` | Farm polygon / draft polyline stroke (weight 3); vertex marker stroke |
| `mapBoundaryFill` | `rgba(74,222,128,0.22)` | Farm polygon fill |
| `mapHalo` | `rgba(10,15,12,0.6)` | Halo line under boundary (weight 6) and under sensor markers (stroke 2 outer ring) |
| `mapVertex` | `#FFFFFF` | Vertex marker fill; pending sensor marker stroke |

| `mapSensorFill` | `rgba(56,189,248,0.2)` | Pending sensor coverage circle fill |

- Map validation feedback is always text in the bottom panel (Notice) + a marker, never color alone.

## Screen Contracts

### S1. Tab bar + center "+" (NAV-01)

Order: **Início · Monitoramento · (+) Adicionar · Alertas · Perfil**. Five equal `flex: 1` slots (72px each at 360).

**AddButton:**
- Slot: `flex: 1`, minHeight 52, `alignItems: center`. Contents: circle → 4 → Caption label "Adicionar" (`textMuted`, 400, same baseline as other tab labels).
- Circle: 56×56, radius pill, bg `primary`, **4px border `card`** (ring separating it from content behind; outer 64), raised with `transform: translateY(-16)` (label not raised — the label sits under the circle with `marginTop: -12` so the label row aligns with the other tabs). Icon `Plus` 32, `onPrimary`, strokeWidth 2.5.
- Shadow: `shadowColor` `text`, opacity 0.2, radius 8, offset 0/4; Android `elevation: 6`; web `boxShadow` equivalent.
- States: default `primary`; pressed `primaryPressed`; web hover `primaryPressed`; web focus inherited 2px `primaryText` outline offset 2 around the circle. Never disabled, never "selected".
- Touch target: whole slot (≥ 72×52) plus the raised circle area (hitSlop top 16).
- a11y: `accessibilityRole="button"`, `accessibilityLabel="Adicionar"`, `accessibilityHint="Cadastrar uma fazenda ou um sensor"`. Not part of the `tablist` semantics (rendered as a sibling button inside the bar).
- `onPress` → `router.push('/adicionar')`. The tab bar is hidden on every `/adicionar/*` route (routes outside `(tabs)`).

#### S3. Step 1 — "Dados da fazenda" (scrolling form)

`ScreenContainer` (ScrollView, `keyboardShouldPersistTaps="handled"`, `KeyboardAvoidingView` padding on iOS). Never contains a map.

1. Title Heading 20/600 "Dados da fazenda" (`accessibilityRole="header"`) → 4 → Label 14/400 muted subtitle.
2. 24 → `Card` (padding 16, fields gap 16):
   - **Nome da fazenda** — `Input`, required, placeholder "Ex.: Sítio Boa Vista", `autoCapitalize="words"`, return next.
   - **CEP** — `Input`, required, placeholder "00000-000", `keyboardType="number-pad"`, `inputMode="numeric"`, mask `00000-000` (stores 8 digits), maxLength 9, `tabular-nums`, `autoComplete="postal-code"`.
     - Lookup fires automatically when the 8th digit is typed (and on blur if 8 digits and not yet looked up). One request per distinct CEP (cached); input stays editable.
     - Helper line states (under the field, Label 14/400): idle → "Digite o CEP para achar a fazenda no mapa." (muted); loading → `ActivityIndicator` small `primaryText` + "Buscando endereço…" (muted); found → `CircleCheck` 16 `success` + "Endereço encontrado. Confira os dados abaixo." (`successText`); not found → Input error "CEP não encontrado. Confira os números ou preencha a cidade e o estado abaixo."; network error → Input error "Não foi possível buscar o CEP. Verifique sua internet." + 8 → `Button secondary sm` "Buscar de novo".

     - **Bairro ou localidade** (opcional) — placeholder "Ex.: Zona rural"

3. Form-level `Notice` slot (16 above button) for location errors on Continuar.

**CEP change after points were drawn:** when the user returns to step 1, edits the CEP to a different value and continues, existing points are cleared and step 2 shows `Notice warning` "O CEP mudou. Marque o limite da fazenda de novo."

## Interaction & Accessibility (additions)

- Every new pressable ≥48×48 (center circle 56; slot ≥72×52), with pressed feedback (`background` bg or `primaryPressed`).
- Map controls (layer toggle, zoom, centralizar, radius stepper, Desfazer/Limpar) are RN elements with PT-BR labels — never Leaflet controls.
- Everything drawn on the map has a text equivalent in MapPanel (points count, area, chosen location, radius, rejection reason). Status lines use `accessibilityLiveRegion="polite"`.
- Validation feedback = text + icon + marker; never color alone.
- Focus order on web: header back → StepHeader → map overlays (toggle, zoom, centralizar) → iframe → MapPanel controls → primary button.
- Reduce motion: map `flyTo/fitBounds` without animation.
- Keyboard never covers the map (inputs only on form steps).
- 360px: all steps verified at 360×640 — map region ≥200 tall with the panel at default font scale (panel ≈ 220–240 incl. notice).
- Haptics: none (expo-haptics not installed; not required).
