## Summary

**Map library: Leaflet 1.9.4 loaded from a pinned CDN with SRI inside a self-contained HTML document, hosted by `react-native-webview` 14.0.1 on native and by an `<iframe srcDoc>` on web.** One HTML/JS map implementation, one JSON message protocol, zero native modules beyond `react-native-webview` (which is in Expo SDK 58's `bundledNativeModules.json`, so it runs in Expo Go AND web). MapLibre RN (`@maplibre/maplibre-react-native` 11.5.1) is rejected: it cannot run in Expo Go (needs config plugin + dev build) and needs a second implementation (`maplibre-gl` 6.18.0) for web. `react-native-maps` 1.29.11 / `expo-maps` 58.0.11 are rejected: no web, Google/Apple base maps with keys, no free satellite+OSM switching in Expo Go. The user's current workflow (Expo Go + web) is preserved.

**Tiles: Esri World_Imagery (satellite, keyless endpoint, attribution required) and tile.openstreetmap.org (street, attribution required, light use).** Both send `access-control-allow-origin: *` and return 200 (verified). Tile URLs must be configurable (constants file) because neither is an SLA-backed commercial service: OSMF may block heavy/commercial use; Esri's keyless endpoint has no current official statement permitting general production use (see Pitfalls / Assumptions).

**CEP: three-step chain.** (1) address: BrasilAPI `/api/cep/v2/{cep}` then ViaCEP fallback (both CORS `*`, verified); (2) coordinates: Nominatim *structured street search* (precise) when a street exists, else BrasilAPI `location.coordinates` (often only city-centroid precision, verified), else Nominatim `postalcode`, else Nominatim city. Every result carries a `precision` flag that drives zoom and the "ajuste manualmente" hint.

**Schema (migration 006):** `properties` gets `cep, address, neighborhood, main_crop, boundary jsonb, center_lat/lng, area_ha`; a BEFORE INSERT trigger validates the GeoJSON and **recomputes area/center server-side**; AFTER INSERT trigger (non-demo only) seeds default thresholds and stamps `onboarding_completed_at`. `sensors` gets `lat, lng, coverage_radius_m`. A `register_sensor` RPC does owner check + point-in-polygon + insert + 30 days of hourly simulated readings in one transaction. `handle_new_user` is recreated without the clone. No PostGIS.

**Primary recommendation:** Build a `MapCanvas` component (`MapCanvas.tsx` native WebView / `MapCanvas.web.tsx` iframe) that is *stateless* — React owns state and pushes a full `scene` JSON to the map; the map only emits `ready` and `tap`. Do all geometry (area, point-in-polygon) in tested pure TS (`src/lib/geo.ts`), and re-validate on the server.

### Pattern 1: Stateless MapCanvas with `scene` protocol
**What:** React owns all state; the map receives one idempotent `scene` object per change and emits only `ready` and `tap`. No command ordering bugs, trivial to unit test, and the same protocol on both hosts.
```ts
// mapProtocol.ts
export type LatLng = { lat: number; lng: number };
export interface MapScene {
  base: 'satellite' | 'street';
  view: { center: LatLng; zoom: number } | { fit: LatLng[]; paddingPx?: number }; // fit => fitBounds
  interactive: 'draw' | 'place' | 'none';       // 'none' = pan/zoom only, taps ignored
  polygon?: { points: LatLng[]; closed: boolean }; // draft or saved farm boundary
  markers?: { id: string; at: LatLng; kind: 'vertex' | 'sensor' | 'pending' }[];
  circles?: { id: string; at: LatLng; radiusM: number; kind: 'sensor' | 'pending' }[];
  style: { stroke: string; fill: string; sensorStroke: string }; // from theme tokens
  labels: { satellite: string; street: string }; // PT-BR for any in-map UI
  rev: number; // increments to re-apply `view` only when it actually changed
}
export type MapEvent =
  | { type: 'ready' }
  | { type: 'tap'; lat: number; lng: number }
  | { type: 'error'; message: string };
```
Host contract: after `ready`, send the latest scene; resend on every change. The in-page code diff-updates layers (remove/re-add small sets; < 200 objects). Only re-run `fitBounds/setView` when `rev` changes so user panning is not fought on every vertex tap.

**Native host (sketch):**
```tsx
// Source: react-native-webview API (injectJavaScript, onMessage, source.html/baseUrl) — verify prop names against v14 docs when implementing
<WebView
  ref={ref}
  originWhitelist={['*']}
  source={{ html, baseUrl: 'https://agroalerta.app' }}   // gives tile requests a valid Referer (OSM policy)
  javaScriptEnabled
  domStorageEnabled
  scrollEnabled={false}
  bounces={false}
  overScrollMode="never"
  nestedScrollEnabled
  setSupportMultipleWindows={false}
  onMessage={(e) => handle(parseMapEvent(e.nativeEvent.data))}
  onLoadEnd={() => ready && push(scene)}
/>
// push: ref.current?.injectJavaScript(`window.__setScene(${JSON.stringify(scene)});true;`)
```

### Pattern 5: Screen layout that avoids gesture and keyboard conflicts
Use **steps, with the map step as a non-scrolling full-height screen**: top = `MapCanvas` (`flex: 1`), bottom = fixed control panel (Desfazer / Limpar / área ha / Continuar). Never nest `MapCanvas` inside `ScrollView` (Android nested-scroll fights; iframe on web swallows wheel/touch). Text inputs (nome, CEP, cultura; sensor nome) live in separate scrolling form steps, so the keyboard never covers the map. The CEP step triggers geocoding and then advances to the map step with the resolved `view`.

### Anti-Patterns to Avoid
- **Imperative command stream** (`addVertex`, `removeVertex`, `setCircle`…): state drift between React and the map. Use full `scene` snapshots.
- **Importing `leaflet`/`react-leaflet` in shared code**: breaks native bundling (needs `window`). The HTML string is the only place Leaflet exists.
- **Client-computed `area_ha` trusted by DB**: recompute in the trigger.
- **Calling `supabase.from('sensors').insert` for new sensors**: sensor + simulated readings must be atomic via the RPC.
- **Keeping `ensure_demo_farm` in the read path.**

## Common Pitfalls

### Pitfall 1: `ensure_demo_farm` self-heal re-creates a demo farm
**What goes wrong:** `getCurrentProperty` calls `rpc('ensure_demo_farm')` whenever zero properties exist → every new empty account instantly gets the cloned farm, defeating DATA-01.
**How to avoid:** Remove that call; make `ensure_demo_farm` a no-op or revoke it. Test: new user → `properties` count 0.

### Pitfall 2: Threshold trigger collides with `clone_demo_farm`
**What goes wrong:** An AFTER INSERT thresholds trigger on `properties` fires for the demo clone too; `clone_demo_farm` then inserts thresholds → unique `(property_id, sensor_type)` violation (the clone's failure is swallowed for signups, but breaks `ensure_demo_farm`).
**How to avoid:** Trigger `when (new.is_demo = false)` and use `on conflict do nothing`.

### Pitfall 3: Demo time-anchoring makes non-demo sensors look offline
**What goes wrong:** `home.ts` shifts only rows with `is_demo === true` (`shiftDemoRow`). If `register_sensor` inserts the sensor with `is_demo=false` but readings with `is_demo=true`, `last_seen_at` is never shifted while `latest.recordedAt` is → inconsistent freshness/offline detection.
**How to avoid:** `register_sensor` inserts the **sensor with `is_demo = true`** (it is a simulated sensor; RLS only blocks *client* inserts of demo rows, definer RPC bypasses). Real ESP32 pairing later inserts `is_demo=false` sensors/readings which are never shifted (matches D-15).
**Second trap:** the offset is ONE value per property from the freshest demo reading. A sensor registered later would otherwise make earlier sensors look older by the registration gap (could exceed the offline threshold). **Fix:** in the RPC, end the new series at `coalesce((select max(recorded_at) from readings where property_id = p and is_demo), date_trunc('minute', now()))` so all demo series of a farm share the same end timestamp. Also update `last_seen_at` of the new sensor to that end.

### Pitfall 4: Esri/OSM grey tiles and policy blocks
Esri World_Imagery may lack high-zoom imagery in rural areas (grey "Map data not yet available" tile). Set `maxNativeZoom: 18`, `maxZoom: 19` (Leaflet overzooms), cap initial CEP zoom at 16, and manually test a rural CEP (e.g. 18150-000 Ibiúna). `[ASSUMED]` — exact native coverage unverified. OSM: attribution must be visible bottom-right, never hidden; do not set `Cache-Control: no-cache`; no prefetch; HTTPS only; keep street layer lazily loaded (only after toggle).

### Pitfall 5: Referer and the web iframe
OSMF requires a valid Referer for browser usage and forbids stripping it. An `<iframe srcDoc>` (about:srcdoc) normally inherits the embedder's referrer, but this was not tested here. **Verify in Chrome devtools** that `tile.openstreetmap.org` requests carry `Referer: http://localhost:8081/` (and the prod origin). Do NOT add `referrerpolicy="no-referrer"` to the iframe or `<meta name=referrer>` to the HTML. If it is missing, fall back to `<iframe src>` served from the app's own origin (e.g. `public/map.html` — Expo web `public/` folder).

### Pitfall 6: Nominatim usage
Max 1 req/s absolute; **no autocomplete / per-keystroke search**; identify the app (browsers send their own UA + Referer automatically, which satisfies the policy; native `fetch` must set a custom `User-Agent: AgroAlerta/1.0` — RN allows setting it; browsers ignore it silently). Cache results in a module-level `Map` keyed by normalized query; trigger geocoding only when the 8th CEP digit is typed or on button press, once per distinct CEP, disable button while in flight. App must be switchable — keep provider base URL in config. OSMF text also states LLM-generated code must follow the policy (done here by design).

### Pitfall 7: BrasilAPI coordinates are often city-level
Verified live: CEP 01310100 (Av. Paulista) returned `-23.5475,-46.63611` (≈2.5 km from the street; São Paulo downtown) and 18150000 returned `-23.65639,-47.2225` (Ibiúna center). Also some valid CEPs 404 (`CepPromiseError`, all upstream services failed; e.g. 13500000, 69900000 failed at test time, ViaCEP returned `{"erro":"true"}` for 13500000). Treat BrasilAPI coords as `precision:'approx'`; prefer Nominatim street geocode when `street` is present (Av. Paulista → `-23.5569,-46.6614`, correct). Always allow manual pan; if all fail → show Notice and open the map on a Brazil default view (center ~ -14.2,-51.9 zoom 4), never block the flow.

### Pitfall 8: WebView/Leaflet quirks
- Leaflet CSS must be loaded in the document `<head>`; container needs explicit `height:100vh; width:100vw` and `html,body{margin:0}`. Call `map.invalidateSize()` on `ready` and on `resize`/ `visualViewport` changes (iframe resize on web, orientation on native).
- Tap vs drag: use Leaflet `map.on('click')` (already ignores drags). Disable `doubleClickZoom` in `draw` mode so rapid vertex taps do not zoom (or keep it but accept). `tap` handler on mobile is built in for Leaflet 1.9.
- Default marker icon images break under bundlers; avoid `L.marker` default icons — use `L.circleMarker` / `L.divIcon` only.
- Do not pass user text into the HTML via string concat; pass data only through `JSON.stringify` of the scene (name labels are optional and must be set with `textContent`, not `innerHTML`).
- Android WebView needs `javaScriptEnabled` (default true) and `domStorageEnabled`; iOS requires `originWhitelist`; `injectJavaScript` string must end with `true;`.
- Offline / CDN blocked: Leaflet script `onerror` → try jsdelivr (same SRI) → emit `{type:'error'}` and show an RN `Notice` "Não foi possível carregar o mapa. Verifique sua internet." with retry (remount via `key`).
- Expo Go: `react-native-webview` is bundled; no dev build needed. Do not use `react-native-maps`/MapLibre in this phase.
- Web CSP: the app declares none today; if a CSP is added later it must allow `script-src` + `style-src` for unpkg/jsdelivr, `img-src` for `server.arcgisonline.com` and `tile.openstreetmap.org`, and `frame-src about: data:` (srcdoc).

### Pitfall 9: Dark theme
The Leaflet container sits on tiles, so only the chrome (panel, buttons) follows the theme (D-11). Provide the toggle satellite/street as an RN control (≥48dp) outside the WebView, not a Leaflet control.

## Code Examples

### geo.ts (pure TS, no deps; spherical formula equal to turf's)
```ts
// Source: spherical polygon area as in Turf area (R = 6378137, Chamberlain & Duquette); point-in-polygon ray casting
export interface LatLng { lat: number; lng: number }
const R = 6378137;
const rad = (d: number) => (d * Math.PI) / 180;

export function polygonAreaM2(ring: LatLng[]): number {
  const n = ring.length;
  if (n < 3) return 0;
  let sum = 0;
  for (let i = 0; i < n; i++) {
    const p1 = ring[i], p2 = ring[(i + 1) % n];     // implicit closure
    sum += (rad(p2.lng) - rad(p1.lng)) * (2 + Math.sin(rad(p1.lat)) + Math.sin(rad(p2.lat)));
  }
  return Math.abs((sum * R * R) / 2);
}
export const polygonAreaHa = (ring: LatLng[]) => polygonAreaM2(ring) / 10_000;

export function pointInPolygon(p: LatLng, ring: LatLng[]): boolean {
  let inside = false;
  for (let i = 0, j = ring.length - 1; i < ring.length; j = i++) {
    const a = ring[i], b = ring[j];
    if (a.lat > p.lat !== b.lat > p.lat &&
        p.lng < ((b.lng - a.lng) * (p.lat - a.lat)) / (b.lat - a.lat) + a.lng) inside = !inside;
  }
  return inside;
}
// ringIsSimple(): O(n²) segment-intersection test over non-adjacent edges (orientation-based) — n<=200, fine.
```
Tests (jest-expo): 1°×1° box at equator ≈ 1.2364e10 m² (±0.5%); small 100 m×100 m square ≈ 1 ha (±1%); concave polygon point-in-polygon; point exactly outside; self-intersecting bow-tie rejected by `ringIsSimple`. Use degrees→meters sanity: at lat -23.6, 0.001° lat ≈ 111 m.

### GeoJSON stored value
`boundary = {"type":"Polygon","coordinates":[[[lng,lat],[lng,lat],...,[lng0,lat0]]]}` — GeoJSON order is **[lng, lat]** and the ring must be closed; the client converts `LatLng[]` ↔ ring in one helper (`toGeoJsonPolygon`/`fromGeoJsonPolygon`) with a test to prevent lat/lng swaps (the classic bug).
