## Pattern Assignments

### `supabase/migrations/006_farms_sensors_map.sql` (migration, CRUD + definer RPC)

**Analog:** `supabase/migrations/004_review_fixes.sql`, `003_demo_farm.sql`, `002_rls.sql`, `005_latest_readings.sql` (header comment style).

**Header convention** (`005_latest_readings.sql` lines 1-12): Portuguese ASCII-only comment block stating dependencies, "NAO e aplicado sozinho ... cole no SQL Editor", idempotency note, and that fresh projects use `setup_completo.sql`. Copy this for 006 (also add the [BLOCKING] manual-apply notice).

**Trigger + definer function pattern** (`004_review_fixes.sql` lines 63-80):
```sql
create or replace function private.sensors_area_same_property()
returns trigger language plpgsql security definer set search_path = '' as $$
begin
  if new.area_id is not null and not exists (...) then
    raise exception 'A area do sensor deve pertencer a mesma propriedade.'
      using errcode = '23514';
  end if;
  return new;
end;
$$;
revoke all on function private.sensors_area_same_property() from public, anon;

create or replace trigger sensors_area_same_property
  before insert or update of area_id, property_id on public.sensors
  for each row execute function private.sensors_area_same_property();
```
Use the same shape for `private.properties_boundary_guard()` (BEFORE INSERT/UPDATE OF boundary) and `private.properties_defaults()` (AFTER INSERT `when (new.is_demo = false)`, `on conflict do nothing` for thresholds - see Pitfall 2).

**Owner check inside definer RPC** (`002_rls.sql` lines 7-12):
```sql
create or replace function private.is_property_owner(p_property uuid)
returns boolean language sql stable security definer set search_path = '' as $$ ... $$;
revoke all on function private.is_property_owner(uuid) from public, anon;
grant execute on function private.is_property_owner(uuid) to authenticated;
```
`register_sensor` must call `private.is_property_owner(p_property)` first.

**RPC grant pattern** (`003_demo_farm.sql` lines 212-229, `ensure_demo_farm`): `create or replace function public.x() ... security definer set search_path = ''` then `revoke all on function ... from public, anon; grant execute ... to authenticated;`. Also: `declare v_uid uuid := (select auth.uid()); if v_uid is null then raise exception 'not authenticated'`.

**Simulated readings generation** (copy the shape from `004_review_fixes.sql` lines 179-206 / `003` same block): `generate_series(v_start, v_end, interval '1 hour')`, `hr` via `at time zone 'America/Sao_Paulo'`, curves `base + 5*sin(2*pi()*(hr-9)/24.0)` (temp), `base - 12*sin(...)` (hum), noise `0.4*sin(h*1.7 + seed*3.1) + 0.3*sin(h*0.53 + seed)`, `round(...::numeric, 1)`, `is_demo = true`; afterwards `update public.sensors set last_seen_at = ...`. Deviation required by RESEARCH Pitfall 3: end timestamp = `coalesce(max demo reading of property, date_trunc('hour', now()))`, sensor inserted `is_demo = true`.

**handle_new_user replacement** (`003_demo_farm.sql` lines 180-199): recreate the same function minus the `begin perform private.clone_demo_farm(...) exception ... end;` block; keep the `producers` insert (`left(coalesce(nullif(trim(new.raw_user_meta_data ->> 'name'), ''), split_part(new.email,'@',1), 'Produtor'), 120)`), the `revoke ... from public, anon, authenticated` and the `grant execute ... to supabase_auth_admin` (lines 204-205) must remain valid (create or replace preserves grants, but re-assert them). Do NOT drop the trigger `on_auth_user_created`.

**RLS context to respect** (`002_rls.sql` line 36, `004` line 53): `revoke update on public.properties/sensors from authenticated` + column grants; client `insert` allowed only with `is_demo = false`; `readings` has no insert policy. New columns are insert-able but not updatable (create-only).

## Shared Patterns

### Service layer + error type
**Source:** `src/services/ServiceError.ts` lines 1-9, `src/services/properties.ts`
**Apply to:** `farms.ts`, `sensors.ts`, `geocoding.ts`. PT-BR message constants (`MSG_LOAD`), `throw new ServiceError(msg, cause)`, rethrow `ServiceError` in catch, wrap anything else. No `supabase.from` in screens/hooks (ESLint enforced).

### Per-user react-query keys
**Source:** `src/hooks/useCurrentProperty.ts`, `src/hooks/useHomeOverview.ts` lines 6-15
**Apply to:** `useFarms`, sensors hooks. `queryKey: ['x', ..., userId, propertyId]`, `enabled: !!userId && !!propertyId`. `useHomeOverview(propertyId)` and `getHomeOverview(propertyId)` already take the property id and handle zero sensors - no signature change needed, just feed the selected farm id.

### Demo data labeling / time anchoring
**Source:** `src/services/home.ts` (`computeDemoOffset`, `shiftDemoRow` from `src/services/demoTime.ts`), `src/services/alerts.ts` lines 50-60 (`fetchDemoOffset`)
**Apply to:** `register_sensor` SQL (readings `is_demo = true`, shared end timestamp) and any UI that shows simulated readings ("Dados demonstrativos").

### Write verification under RLS
**Source:** `src/services/onboarding.ts` lines 15-17, 29-34 (`.select('id')` + `hasRows`)
**Apply to:** every client insert/update in `farms.ts`.

### Theming / styles
**Source:** `src/components/ui/EmptyState.tsx` lines 19-36, `TabBar.tsx` lines 41-69
**Apply to:** all new components: `const { colors } = useTheme(); const styles = useMemo(() => StyleSheet.create({...}), [colors]);` tokens only, no hex (enforced by `scripts/check-ui-rules.mjs`). Colors for the map HTML must arrive via `scene.style` from `colors.map*`.

### Jest harness for Supabase services
**Source:** `src/services/onboarding.test.ts` lines 1-41
