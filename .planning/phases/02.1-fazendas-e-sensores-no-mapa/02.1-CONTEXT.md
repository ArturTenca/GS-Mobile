# Phase 2.1: Fazendas e sensores no mapa - Context

**Gathered:** 2026-11-12
**Status:** Ready for planning
**Source:** User request in /gsd-plan-phase + 4 decisions via AskUserQuestion (inserted phase)

<domain>
## Phase Boundary

New accounts start EMPTY (no cloned demo farm). The producer builds their own farm through a new center "+" action in the tab bar:

1. **Adicionar fazenda (terreno):** basic info + a world map. Typing a CEP moves the map to that address. The producer taps points on the map that delimit the farm boundary (polygon), then saves.
2. **Adicionar sensor:** select one of their farms → the map opens fitted to that farm's polygon → tap to place the sensor point (inside the farm) → choose sensor type and the coverage radius it can analyze → save. Only then is the sensor registered.
3. Registered sensors receive **simulated readings** (clearly labeled demonstrative) so Início, Monitoramento and condition logic work until real ESP32 data exists.

Requirements: DATA-01, NAV-01, FARM-01, FARM-02, FARM-03, FARM-04, SENS-01, SENS-02, SENS-03, MAP-01 (new, see REQUIREMENTS.md). Supersedes: FND-08 cloning for new users, ONB-01 mandatory onboarding screen, MON-08 add-sensor form (Phase 3 keeps listing/detail/charts).

Not in this phase: sensor detail charts / Histórico (Phase 3), alert center + generated alerts from simulated readings (Phase 4), editing/deleting farm polygons or sensors (later; create-only here unless trivial), real ESP32 ingest, real weather.

</domain>

<decisions>
## Implementation Decisions

### Dados iniciais
- **D-01:** New signups get **no mock data**: drop/neutralize the `clone_demo_farm` call in the signup trigger (keep the `producers` row creation). Existing test accounts keep whatever they have (no destructive migration); optionally ship a separate, manual cleanup SQL the user can run — never auto-delete.
- **D-02:** The mandatory "Configure sua propriedade" onboarding screen is **removed**. A producer with zero farms lands on Início, which shows an empty state ("Cadastre sua primeira fazenda" + button) that opens the add-farm flow. Monitoramento / Alertas show matching empty states. `onboarding_completed_at` stops gating navigation (may be set when the first farm is saved).

### Navegação (user chose "4 abas + botão")
- **D-03:** Tab bar = **Início · Monitoramento · (+) · Alertas · Perfil**. The center (+) is a raised **green circle** (primary color, white plus icon, ≥56dp, accessible label "Adicionar"), not a regular tab: pressing it opens an "Adicionar" chooser (sheet/modal or screen) with two options: **Fazenda** and **Sensor** (Sensor disabled with hint when no farm exists).
- **D-04:** **Análises leaves the tab bar** and becomes reachable from Monitoramento (entry card/link); its route keeps working. Phase 5 builds its content.

### Fazenda (terreno)
- **D-05:** Basic info: **nome da fazenda** (required), **CEP** (required, 8 digits, mask 00000-000), endereço/cidade/UF auto-filled from the CEP (editable), **cultura principal** (optional). Area in hectares is **computed** from the polygon and shown, not typed.
- **D-06:** CEP lookup → coordinates → map flies there (zoom ~16). Use free Brazilian services (e.g. BrasilAPI CEP v2 / ViaCEP for address + an OSM geocoder fallback for coordinates) behind a service in `src/services/` (adapter pattern). If coordinates cannot be resolved, center on the city and tell the user to pan manually. CEP precision is street/neighborhood level — the user adjusts by panning/tapping. Respect the providers' usage policies (identify the app generically, debounce, no bulk calls).
- **D-07:** Boundary drawing: tap to add vertices, polygon drawn live; controls **Desfazer último ponto**, **Limpar**; save requires ≥3 points. Store as GeoJSON-compatible polygon (lat/lng) on the property (e.g. `properties.boundary jsonb` + `center_lat/center_lng` + `area_ha`), validated server-side (CHECK / function) where practical.
- **D-08:** A saved farm = a `properties` row (`is_demo = false`) owned by the user. Multiple farms per producer are now allowed in the UI.
- **D-09:** **Fazenda selecionada:** with more than one farm, Início and Monitoramento show the currently selected farm with a simple selector (persisted per user, e.g. zustand + storage). Default = most recently created farm. Kept minimal (not the full SCL-01 switcher UX).

### Mapa (user chose "Satélite + alternar ruas")
- **D-10:** Default base layer **satellite imagery**, with a toggle to a **street map**. Free tile sources with proper attribution shown on the map. Must work on **web and native** with one shared implementation as far as possible (researcher to pick: e.g. Leaflet rendered in DOM on web and in a WebView on native, or MapLibre). No paid API keys required for v1.
- **D-11:** Map interactions must work with touch and mouse; large controls (≥48dp); PT-BR labels; follows dark/light theme for its surrounding chrome.

### Sensor (user chose "Raio em metros")
- **D-12:** Flow: choose farm (Select) → map fits the farm polygon (polygon drawn) → tap to place the sensor point; the point **must be inside the farm polygon** (reject with a PT-BR message otherwise) → choose **tipo** (temperatura, umidade do ar, umidade do solo — existing enum, extensible) → **nome** (prefilled e.g. "Umidade do solo 1", editable) → **raio de cobertura em metros** (slider/stepper with presets, e.g. 10–500 m, default 50 m) with a live coverage circle → **Registrar sensor**.
- **D-13:** Store on `sensors`: `lat`, `lng`, `coverage_radius_m` (CHECK > 0), unit derived from type. `area_id` stays optional.
- **D-14:** Map in the sensor flow also shows the farm's already-registered sensors and their circles.

### Leituras simuladas (user chose "Simular leituras")
- **D-15:** When a sensor is registered, the backend generates simulated history for it (e.g. a SECURITY DEFINER RPC or trigger generating ~7–30 days of realistic readings by type with daily cycles), all rows **`is_demo = true`**, and sets `last_seen_at`. Default thresholds for the farm are created when the farm is created (temp 10–32, air 30–85, soil 25–80). The existing demo time-anchoring (Phase 2 D-08) keeps them looking fresh; when a real ESP32 arrives, its rows are `is_demo = false` and are never shifted.
- **D-16:** Wherever simulated readings appear, the UI labels them "Dados demonstrativos" (FND-09). Generating alerts from simulated readings is Phase 4.

### Claude's Discretion
- Exact map library, tile providers, geocoding providers (within D-06/D-10 constraints) — researcher decides and documents attribution/usage limits.
- Screen structure of the "Adicionar" chooser and the two flows (single scrolling screen vs. steps), as long as map + form are usable at 360px.
- How Início/Monitoramento adapt to the selected farm and zero-sensor states (reuse Phase 2 overview service).
- Whether to keep the old demo `is_demo` farm rows of existing accounts visible (they remain valid data).

</decisions>
