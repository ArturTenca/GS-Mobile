<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| e-mail link/deep link -> app | URL fragment carries access/refresh tokens; any app or page can open `agroalerta://` |
| user input -> reset form | New password, e-mail |
| Supabase redirect allow-list -> `redirectTo` | Controls where recovery tokens are sent |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Spoofing | Open redirect via `redirectTo` | mitigate | Supabase redirect allow-list set in plan 02 checkpoint (exact scheme/hosts); `redirectTo` built only by `Linking.createURL('reset-password')`, never from user input |
| T-06-02 | Information disclosure | Account enumeration on reset | mitigate | Same "Verifique seu e-mail" state and null error regardless of existence; only rate-limit surfaces |
| T-06-03 | Tampering | Forged recovery URL with attacker tokens | mitigate | `setSession` only accepts tokens Supabase validates server-side; `classifyRecoveryUrl` requires `type=recovery` and both tokens; invalid tokens lead to `invalid` state |
| T-06-04 | Information disclosure | Tokens in logs/URL | mitigate | Never log URLs or params; parser returns values to memory only; hash cleared by supabase-js on web |
| T-06-05 | Elevation/Spoofing | Weak new password | mitigate | `validateNewPassword` (min 8, max 128) client-side plus dashboard min length 8 server-side |
| T-06-06 | Denial of service | Backend unreachable | mitigate | DatabaseGate with retry, ErrorBoundary; no blank screens |
| T-06-07 | Repudiation | Link scanners consuming one-time token | accept | UX handled by `invalid` state with "Enviar novo link" (Pitfall 7) |
</threat_model>
