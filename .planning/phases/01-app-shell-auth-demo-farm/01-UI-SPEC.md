# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Stack: Expo SDK 58 + React Native + RN Web. Styling = `StyleSheet` + `src/theme/tokens.ts` (single source of truth, light + dark). NativeWind is NOT used (RESEARCH "NativeWind decision", D-13 fallback). Never hardcode a hex value outside `tokens.ts`.
> All user-facing copy is PT-BR, short, field language. Copy in this file is final; executors must use it verbatim.

## Typography

Exactly 4 sizes and 2 weights in Phase 1. Line heights are absolute px (RN), ratios shown for reference.

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Caption | 12px | 400 regular (600 for Badge text) | 16px (1.33) | Tab bar labels, Badge/DemoBadge text, footnotes |
| Label | 14px | 600 semibold for field labels; 400 regular for helper, error, secondary text | 20px (1.43) | Field labels, helper/error text, secondary card info, links, segmented tab labels |
| Body | 16px | 400 regular; 600 semibold for button text and card primary info | 24px (1.5) | Input text, body copy, button labels, card primary line |
| Heading | 20px | 600 semibold | 28px (1.4) | Screen titles, auth wordmark, state titles (Empty/Error), Modal title |

- Weights: **400 (Inter_400Regular)** and **600 (Inter_600SemiBold)** only. Gemma's `font-medium` (500) maps to 600. Loading 500/700 is allowed by RESEARCH but they are not used in Phase 1 screens. Display size (28+/700) for the "Condição da propriedade" indicator is a Phase 2 decision.
- Numerals: `fontVariant: ['tabular-nums']` on any numeric reading/count (e.g. Início counts).
- Text scaling: `allowFontScaling` stays on everywhere. Tab labels use `maxFontSizeMultiplier={1.2}`, `numberOfLines={1}`. Buttons and inputs grow in height with text (use `minHeight`, never fixed `height`).
- Text color: primary text = `text`; secondary = `textMuted`. Never put body text on `primary` except button labels (`onPrimary`).

## Layout & Shell

### App column (web, D-14)
Outer `View` `flex: 1`, bg `backgroundOuter`, `alignItems: 'center'`. Inner `View` `flex: 1, width: '100%', maxWidth: 500`, bg `background`. Tab bar renders inside the column. Native: same structure (maxWidth harmless).

`SafeAreaView` top edge; `ScrollView` (`keyboardShouldPersistTaps="handled"`), `paddingHorizontal: 16`, `paddingTop: 16`, `paddingBottom: 24`, vertical gap between sections 24. Status bar style follows theme (`dark-content` light / `light-content` dark).

### ScreenHeader
56px row, `paddingHorizontal: 16`. Início: `Logo size={32} withWordmark`. Other tabs: title text (Heading 20/600, `text`), `accessibilityRole="header"`. No back buttons, no right-side actions in Phase 1.

### TabBar (D-15, FND-02) — `src/components/layout/TabBar.tsx`
- Container: bg `card`, top border 1px `border`, `paddingTop: 8`, `paddingBottom: 8 + insets.bottom`, row of 5 equal items (`flex: 1`). No center button, no sheet, no shadow, no blur.
- Order + icons (RESEARCH Pattern 2): Início `House` · Monitoramento `Activity` · Alertas `Bell` · Análises `ChartLine` · Perfil `User`. Icon 24.
- Item: `Pressable`, `minHeight: 52`, column, centered: indicator pill (56x32) containing icon, 4px gap, label Caption 12/400.
- Inactive: icon + label `textMuted`, stroke 2, pill transparent.
- Active: icon + label `primaryText`, icon stroke 2.5, pill bg `primarySoft` (shape cue, so selection is not color-only).
- Pressed: pill bg `primarySoft` at 60% opacity for inactive items (feedback), 0ms delay.
- a11y: container `accessibilityRole="tablist"`; item `accessibilityRole="tab"`, `accessibilityState={{ selected }}`, `accessibilityLabel` = full tab name. Badge slot (`tabBarBadge`) reserved for Phase 4 Alertas count; not rendered in Phase 1.
- Label fit: labels use exact names. At 360px width "Monitoramento" (~82px at 12px) may exceed the item. Apply `numberOfLines={1}`, `letterSpacing: -0.2`, `paddingHorizontal: 0`, and on native `adjustsFontSizeToFit minimumFontScale={0.85}`. Executor MUST check 360px and 390px on web; if it still clips on web, show visible label "Monitorar" while `accessibilityLabel` stays "Monitoramento" (assumption A3).

## Screen Contracts

### S1. Auth — `(auth)/index.tsx` (D-01, D-02, D-04, D-16)

**Focal point:** the primary button inside the important card.

Layout (top to bottom), ScrollView inside `KeyboardAvoidingView`, content `maxWidth 390`, centered, `paddingHorizontal 16`, `paddingTop 48`:
1. `Logo size={56} withWordmark` stacked, centered; 8 below: tagline (14/400 `textMuted`, centered).
2. 32 gap → `Card variant="important"`, padding 24.
3. Inside card: `Notice warning` (only when Supabase not configured) → `Tabs` [Entrar | Criar conta] → 24 gap → form (fields gap 16) → form-level `Notice` (error / cooldown) → 8 gap → primary `Button md fullWidth`.

**Tab "Entrar":** E-mail (`keyboardType="email-address"`, `autoCapitalize="none"`, `autoComplete="email"`, `textContentType="emailAddress"`, return key "next") → Senha (secure + eye, `autoComplete="password"`, return key "go" submits) → right-aligned ghost link "Esqueci minha senha" (14/600 `primaryText`, 48 target) → `Button` "Entrar".
**Tab "Criar conta":** Nome (`autoComplete="name"`, `autoCapitalize="words"`) → E-mail → Senha (secure + eye, `autoComplete="new-password"`, helper "Mínimo de 8 caracteres.") → `Button` "Criar conta". Exactly 3 fields (D-04). On success the user is signed in immediately (D-02) and routed to Início.

- Switching tabs keeps the typed e-mail, clears errors and password.
- Validation on submit; field errors inline under the field; server/auth errors in form-level `Notice error`.
- Cooldown (D-16, client only): after 5 failed logins, `Notice warning` with live countdown starting at 30s, all fields + button disabled until 0, then auto re-enable. No 24h block UI.

**Forgot password view (same route, replaces the Tabs + form inside the card):**
- Title "Recuperar senha" (Heading) → 12 → body (14/400 muted) → 24 → E-mail field (prefilled from Entrar) → `Button` "Enviar link" → ghost link "Voltar para entrar" (centered).
- **E-mail enviado** state (D-03): 48 circle `successSoft` with `MailCheck` 24 `success` → title → body (shows the typed e-mail in 14/600) → `Button secondary md fullWidth` "Voltar para entrar" → ghost "Reenviar link" disabled with countdown for 60s (assumption A2), then enabled.
- Always show the same "enviado" state whether or not the e-mail exists (RESEARCH Pattern 4).

## Interaction & Accessibility (FND-10)

- Every icon-only control has `accessibilityLabel` (PT-BR). Decorative icons inside labeled controls are hidden from screen readers.
- Every state title (Empty/Error/success) is `accessibilityRole="header"`; error and cooldown messages use `accessibilityLiveRegion="polite"` (Android) and `AccessibilityInfo.announceForAccessibility` (iOS) on appear.
- Status/condition is always icon + text + color (Status contract).
- Touch targets >= 48 everywhere; tab items >= 52.
- Keyboard: form return keys chain fields ("next"), last field submits. On web, Enter submits; Tab order follows visual order; focus ring visible.
- After submit errors, focus moves to the first invalid field.
- Text scaling to 200% must not overlap or clip: use `minHeight`, wrapping text, ScrollView on all screens. Only tab labels are capped (`maxFontSizeMultiplier 1.2`).
- No hover-dependent UI (touch first). Pressed feedback on every `Pressable`.
- Motion: tab change instant; Modal fade 150ms; no spinners longer than needed — loading labels always present with spinner.
