<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (anon/authenticated key) -> PostgREST | Untrusted queries; RLS is the only enforcement |
| client -> public RPC | `ensure_demo_farm()` is the only client-callable function |
| auth.users trigger -> public tables | Definer function runs with elevated rights |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information disclosure | Cross-tenant read of any table | mitigate | RLS enabled on all 10 tables in the same migration set; policies keyed on `owner_id = (select auth.uid())` or `private.is_property_owner()`; no `using (true)`; anon has no policy |
| T-02-02 | Elevation of privilege | Calling clone_demo_farm for another uid via RPC | mitigate | Function lives in `private` schema, `revoke all ... from public, anon, authenticated`; only `public.ensure_demo_farm()` exposed and it uses `auth.uid()` |
| T-02-03 | Tampering | Client editing `is_demo`, readings, risk data or other alert columns | mitigate | Column-level `grant update` (alerts: status only; properties: name, city, state; producers: full_name, onboarding_completed_at); insert policies `with check (is_demo = false)`; readings/risk/climate are select-only |
| T-02-04 | Denial of service | Seed bug blocking signups | mitigate | Clone wrapped in exception block raising a warning only; `ensure_demo_farm()` self-heals |
| T-02-05 | Information disclosure | Service-role key leaking into `.env`/repo | mitigate | Checkpoint tells user to use only URL + anon/publishable key; `.env` git-ignored (plan 01) |
| T-02-06 | Spoofing | Open redirect through reset `redirectTo` | mitigate | Redirect URL allow-list in the dashboard (exact scheme/hosts) |
</threat_model>
