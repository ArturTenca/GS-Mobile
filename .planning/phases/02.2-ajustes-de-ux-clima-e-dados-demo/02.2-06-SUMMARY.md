# Phase 02.2 Plan 06: Monochrome Themed Map Summary

The farm and sensor maps now render a grey base map (light grey in light theme, inverted dark grey in dark theme; grayscale satellite, darkened in dark theme). The grey comes from one `MAP_TILE_FILTERS` table applied as a CSS filter on the Leaflet tile pane over the same keyless OSM and Esri tiles, so the overlays stay in brand colors. No CARTO tiles, no API keys, CSP unchanged.

## What was built

- **mapTiles.ts:** `MapTheme` type and `MAP_TILE_FILTERS` (`street`/`satellite` x `light`/`dark`, the plan's starting values, documented as tunable against `colors.background`). There is a comment explaining why CARTO is not used. `TILE_LAYERS` is unchanged.
- **mapProtocol.ts:** `MapScene.theme: MapTheme`, which is not part of `rev`, so changing the theme never re-fits the view. `SceneStyle.mapBg` is filled from `colors.background` by `sceneStyleFromColors`.
- **mapHtml.ts:** `tileFilterCss()` builds `.base-{layer}` and `html[data-theme="dark"] .base-{layer}` rules from constants only and adds them to the `<style>` block. The new `applyTheme(s)` in the page script does four things:
  - sets `data-theme` to `'dark'` only when `s.theme === 'dark'`
  - paints the body and map container with `s.style.mapBg`
  - removes every `base-*` class from `map.getPane('tilePane')`
  - adds the class for the current base layer, leaving Leaflet's own pane classes alone
  The HTML is still built once, and theme changes arrive through the normal full-scene re-post.
- **MapStage.tsx:** adds `theme` from `useTheme()` to the full scene. The scene prop type now omits `theme`. There is no key change and no remount, so center, zoom, drawn points and the pending sensor survive a theme change.
- **MapLayerToggle.tsx:** options are now "Mapa" (street, first) and "Satélite". The "Tipo de mapa" accessibility label and the 48dp segments are unchanged.
- **FarmMapStep / SensorMapStep:** `useState<MapBase>('street')`, so each flow entry opens on "Mapa".
