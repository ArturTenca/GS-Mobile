# Phase 2.2: Ajustes de UX, clima e dados demo - Context

**Gathered:** 2026-11-12
**Status:** Ready for planning
**Source:** User feedback after testing Phase 2.1 in the browser (5 change requests + screenshot of the FarmSelector sheet spanning the full width). Decisions below were made by Claude from the request; no extra questions asked.

<domain>
## Phase Boundary

Five follow-up changes on top of Phase 2.1 (which is still awaiting UAT closeout — 2.2 builds on its code):

1. **Perfil com configurações** — theme (claro / escuro / sistema) and more settings.
2. **Popups centralizados** — every popup/sheet appears centered, sized to its content (the FarmSelector/Select sheet currently spans the whole screen width at the bottom).
3. **Previsão do tempo no Início** — real weather API, current conditions + the days of the current week with weather icons.
4. **Mapa monocromático** — the farm/sensor maps use a monochrome base that follows the app's light/dark theme.
5. **Análises com dados demo** — entering Análises (from Monitoramento) asks whether to generate demonstrative data; on confirm, data for charts of ALL sensors of the selected farm is generated and shown as charts.

Requirements (new, add to REQUIREMENTS.md): PRF-06, UX-01, WX-01, MAP-02, DEMO-02, ANL-01 (see below).

Not in this phase: sensor detail screen + Histórico (Phase 3), alert generation from readings and push (Phase 4), plain-language risk analysis text (Phase 5 RISK-*), editing farms/sensors.

</domain>

<decisions>
## Implementation Decisions

### 1. Perfil e configurações (PRF-06)
- **D-01:** Perfil becomes a settings screen with sections (rows ≥48dp, PT-BR):
  - **Conta:** nome (editable, updates `producers.full_name` or the existing name column), e-mail (read-only).
  - **Aparência:** Tema = **Sistema / Claro / Escuro** (segmented control or 3 ChoiceCards). Default "Sistema". Persisted (zustand persist, same storage pattern as `selectedFarm`). `ThemeProvider` reads the persisted preference (today its override is in-memory only).
  - **Fazenda:** fazenda padrão (select among the user's farms — reuses the selectedFarm store), "Adicionar fazenda" shortcut.
  - **Notificações:** toggles Alertas críticos / Avisos / Resumo diário — saved locally (persisted store) as preferences only; real push wiring is Phase 4 (show a short note on web: "Notificações push só no app do celular").
  - **Unidades:** temperatura °C / °F (persisted; applied wherever temperature is formatted via a single formatter in `src/lib/format.ts`).
  - **Dados:** explanation of "Dados demonstrativos" + where they come from.
  - **Sobre:** versão do app (expo-constants), fontes (Open-Meteo, OpenStreetMap/CARTO/Esri attribution).
  - **Sair** (existing logout) at the bottom, destructive style with confirmation.
- **D-02:** Settings storage: one persisted zustand store `src/stores/preferences.ts` (theme, tempUnit, notification toggles). Account fields go through `src/services/producers.ts`.

### 2. Popups (UX-01)
- **D-03:** ALL popups/dialogs/sheets (`Select`, `FarmSelector`, confirm dialogs like "Descartar fazenda?", "Limpar", logout, the new demo-data prompt) render as a **centered card**: `maxWidth` ~400, width `100%` minus 16px gutters, height = content (`maxHeight` ~80% with internal ScrollView for long option lists), dimmed backdrop, close on backdrop/X/Android back. No full-width bottom sheets. Unify on the existing `src/components/ui/Modal.tsx` (already centered) — fix `Select`/`FarmSelector` to use it.
- **D-04:** Confirmations must not use `Alert.alert` / `window.confirm` (inconsistent on web); use a shared `ConfirmDialog` built on `Modal`.

### 3. Previsão do tempo (WX-01)
- **D-05:** Provider: **Open-Meteo** forecast API (`https://api.open-meteo.com/v1/forecast`) — free, no API key, CC BY 4.0; attribution "Dados do tempo: Open-Meteo.com" shown under the card. Params: `latitude`, `longitude` (selected farm `center_lat/center_lng`), `current=temperature_2m,relative_humidity_2m,weather_code,wind_speed_10m,precipitation`, `daily=weather_code,temperature_2m_max,temperature_2m_min,precipitation_probability_max`, `timezone=auto`, `forecast_days=7`.
- **D-06:** Service `src/services/weather.ts` (adapter, typed, validates the response, ServiceError on failure) + hook `useWeatherForecast(farmId/coords)` with React Query (staleTime 30 min, keyed by rounded coords). Pure WMO-code → {label PT-BR, icon} mapper in `src/features/weather/` with unit tests. Icons from lucide-react-native (Sun, CloudSun, Cloud, CloudFog, CloudDrizzle, CloudRain, CloudSnow, CloudLightning).
- **D-07:** Início: the climate card shows **agora** (temp, condition label + icon, umidade, vento, chuva) and a **horizontal row of the current week's days** — 7 days starting today, labeled "Hoje", "Qua", "Qui"… (PT-BR short weekday), each with icon, máx/mín and chance de chuva. Fits 360px (horizontal scroll allowed inside the card, no page horizontal scroll). Respects the °C/°F preference.
- **D-08:** This is **real** data (not demo) → no "Dados demonstrativos" badge on it; it replaces the demo `climate_snapshots` card on Início. User explicitly requested a real weather API — this overrides the earlier "no real weather APIs" guidance for the forecast only (risk analyses stay demo). Farm without coordinates (old demo farm of legacy accounts) → fall back to the demo snapshot card or a "Previsão indisponível para esta fazenda" state. Loading skeleton + error state with "Tentar novamente".

### 4. Mapa monocromático (MAP-02)
- **D-09:** The base map is **monochrome and follows the app theme**: light theme → light grey map, dark theme → dark grey map. Default layer becomes **"Mapa"** (monochrome); the toggle offers **Mapa / Satélite**. Satellite is also rendered desaturated (grayscale, slightly darkened in dark theme) so the whole map stays monochrome; the farm polygon, sensor points and coverage circles keep the brand green/accent colors so they stand out.
- **D-10:** Implementation (researcher confirms): preferred = CARTO basemaps `light_all` / `dark_all` (free, attribution "© OpenStreetMap contributors © CARTO") configured in `src/lib/mapTiles.ts`, or OSM tiles with a CSS `filter` on the Leaflet tile pane (`grayscale(1)` light; `grayscale(1) invert(1) brightness(…)` dark). Theme is passed into the map scene (`mapProtocol`) so switching theme updates the map live, on web (iframe) and native (WebView). Applies to both the farm and the sensor flows.

### 5. Análises com dados demonstrativos (DEMO-02, ANL-01)
- **D-11:** When the producer opens Análises (from Monitoramento) for the selected farm **that has sensors** and the farm has **no generated demo dataset yet** (`properties.demo_data_generated_at is null`), a centered popup asks: "Gerar dados demonstrativos?" — "Vamos criar 30 dias de leituras simuladas para todos os sensores de {fazenda}, para você ver os gráficos. Os dados ficam marcados como demonstrativos." Buttons **Gerar dados** / **Agora não**. "Agora não" closes it (asked again next visit); the page also has a "Gerar dados demonstrativos" / "Regerar dados" button. Farm with zero sensors → empty state "Cadastre um sensor para ver análises" + button to add sensor (no popup).
- **D-12:** Backend: migration `007_demo_dataset.sql` — `properties.demo_data_generated_at timestamptz` + SECURITY DEFINER RPC `public.generate_demo_dataset(p_property_id uuid)`:
  - checks `auth.uid()` owns the property; rate-limit-ish guard (e.g. not more than once per minute);
  - for every sensor of that farm: delete its existing `is_demo` readings and generate **30 days hourly** realistic readings by type (daily cycles + noise, a few excursions outside the farm thresholds so charts show warnings), `is_demo = true`; update `last_seen_at`;
  - sets `demo_data_generated_at = now()`; returns counts.
  - Reuse the generator from `register_sensor` (006) — refactor into a shared private function if practical. Real readings (`is_demo = false`) are never touched. Update `supabase/setup_completo.sql`. User applies SQL manually (**[BLOCKING] checkpoint**), plus anon probe script like `probe-006`.
- **D-13:** Análises screen content: farm selector (when >1 farm) → period filter chips **24h / 7 dias / 30 dias** → one **chart card per sensor** (line chart, react-native-gifted-charts per CLAUDE.md stack; name, type, unit, latest value, min/máx/média of the period, threshold band or reference lines when thresholds exist) → "Dados demonstrativos" badge on the section. Charts must work on web and native, ≥360px. Demo time-anchoring (Phase 2 D-08) applies. Downsample for 30d (e.g. 6-hour buckets) to keep charts fast.
- **D-14:** Data goes screens → hooks → `src/services/*` (`readings.ts` history query by sensor ids + period, `demoData.ts` for the RPC). After generation, invalidate Início/Monitoramento/Análises queries.

## Existing Code Insights

- `Modal.tsx` is already a centered card (maxWidth 400); the full-width bottom sheet in the screenshot comes from `Select`/`FarmSelector` — RN `Modal` renders outside `AppColumn`, so width must be capped inside the popup itself.
- `ThemeProvider` keeps the override only in React state (lost on reload) — needs persisted preference with "system" option.
- Map tiles are centralized in `src/lib/mapTiles.ts`; scene/event protocol in `mapProtocol` — add theme + monochrome there.
- Service-layer rule (ESLint), StyleSheet + tokens only (`scripts/check-ui-rules.mjs`), PT-BR copy, 48dp targets.
- New SQL = migration `007_*` + `setup_completo.sql`; user applies manually.
